# Pattern: icon asset pipeline — master SVG, lockfile-safe rasterizer, prebuild gate

- Type: pattern
- Date: 2026-06-06
- Work unit: 017-app-icon-branding
- Related: [[018-decision-eas-ios-release-workflow]] / [[021-decision-gh-actions-ios-release-orchestration]]
  (the auto-submit-on-merge pipeline that makes the pre-merge prebuild gate load-bearing)

Every app-icon surface (iOS icon, Android adaptive set, web favicon, Android splash
glyph) is rasterized from one master `assets/images/vital-icon.svg` by
`scripts/generate-icons.mjs`. The script is **local-only, one-time, manual**: the
committed PNGs are the artifacts; CI and deploy never run it.

Load-bearing details:

- **Lockfile-safe rasterizer.** The script's dependency is installed with
  `npm install --no-save @resvg/resvg-js@2.6.2` (pinned) so `package.json` and
  `package-lock.json` show zero diff. resvg ships platform-specific optional binaries —
  exactly the class that triggered the npm/cli#4828 missing-optional-dep lockfile bug
  this repo was bitten by (commit `d16484e` healed `@emnapi/*` etc. after `npm ci` broke
  on DigitalOcean). Never add such a package to the lockfile for a script CI doesn't run.
- **Prebuild gate.** This is a CNG repo (`/ios`, `/android` gitignored) — the iOS asset
  catalog is generated by `expo prebuild` at EAS build time, and merges to `main`
  auto-build + auto-submit to the App Store. The pre-merge validation gate is
  `npx expo prebuild -p ios --no-install --clean`, asserting the generated
  `ios/*/Images.xcassets/AppIcon.appiconset/` is populated from `icon.png`; remove the
  generated native dirs afterwards.
- **GOTCHA — prebuild mutates package.json.** `expo prebuild` silently rewrites the
  `ios`/`android` npm scripts (`expo start --ios` → `expo run:ios`). Revert with
  `git checkout package.json` after the gate, and check the lockfile/package zero-diff
  criterion AFTER the prebuild gate, not before.
- **GOTCHA — extraction contract vs. its own docs.** The generator extracts `<g id="bg">`
  and `<g id="pulse">` from the master SVG by regex. The SVG's doc comment originally
  contained the literal string `<g id="bg">`, so the regex anchored inside the comment
  and produced malformed variant SVGs ("root node was opened but never closed"). The
  extraction-target SVG's comments must never contain the markup the contract describes
  (the fixed comment says `group "bg"`).
- **Geometry coupling.** The script's `GLYPH` bbox constants (`{x:72, y:242, w:880,
  h:486}`) are derived from the SVG trace geometry (stroke 76 → 38px half-extent; dot
  cx 916 + r 36). Redrawing the trace requires updating the constants in the same change.
- **iOS sourcing.** `ios.icon` (Icon Composer `.icon` bundle) was deliberately deleted:
  prebuild copies such a bundle verbatim for Xcode to render at build time, so it can't
  be validated locally — a malformed bundle would first surface in the auto-submitting
  EAS build. The flat top-level 1024² `icon.png` is the locally-validated source for the
  standard asset catalog instead.
- Android adaptive layering: the brand gradient lives in the **background** layer PNG
  (`adaptiveIcon.backgroundColor #208AEF` is only a fallback, inert while
  `backgroundImage` is set); the foreground is the white glyph alone, inside the central
  676px (66%) safe zone; monochrome is byte-identical to the foreground by design —
  Android tints it itself.

When to reach for this: any icon/branding rework, any change that adds a
platform-binary dev tool for a local-only script, and any pre-merge validation of
artifacts that EAS/prebuild generates at build time.
